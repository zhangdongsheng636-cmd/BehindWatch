# BehindWatch · 身后来人提醒

Windows 10/11 x64 本地摄像头人体监测工具。画面和检测均在本机处理；程序不上传、不联网更新、不录像。默认仅记录文字事件，不保存截图。

**直接使用**

1. 完整解压 Windows ZIP，双击 `BehindWatch.exe`。不要只复制 EXE，旁边的 `_internal` 文件夹包含运行库和本地模型。
2. 在摄像头列表选择设备。常规模式优先，不能打开时尝试兼容模式。列表中的同一摄像头可能有两个后端入口，不代表有两只摄像头。
3. 点击“预览画面”。倒装的镜头在“设置 → 画面与检测”中打开 180° 旋转或水平翻转。
4. 点击“框选走廊”，在画面中拖动检测矩形。绿色虚线是检测区；用“添加排除区”排除自己或固定座位。也可用“区域数值”输入百分比。旋转/翻转或更换设备后重新框选。
5. 点击“开始监测”。开始监测后，该按钮变为“停止监测”；停止会释放摄像头。关闭主窗口则继续在托盘运行。托盘图标双击打开，右键可退出。
6. 用“测试提醒”确认当前提醒方式。默认边角弹窗和图标；系统通知、声音、任务栏闪烁和边框闪烁在设置中单独开启。勿扰开启后仅更新图标，但仍记事件日志。

**先调这三个参数**

- 频繁被远处路人触发：选择低灵敏度，或提高最小人体高度占比、缩小检测区域。
- 近处来人提醒太迟：降低确认时间。更短的确认时间也更容易提醒快速闪过的人。
- 同一人停留时太频繁：增加重复提醒间隔；设置为 0 表示该短期轨迹只提醒一次。

默认每秒检测 5 次、确认 0.6 秒、重复间隔 30 秒。不同人的事件分别判断，对外提醒最短间隔 3 秒以避免弹窗/音效叠加。

**使用注意**

- 镜头必须真实朝向走廊；图像旋转不会改变镜头视野。自己占据前景或椅背挡住走廊时，先调整安装位置。
- 检测区要求人体框中心在区内，且至少约 35% 的框面积落入检测区。排除区以人体框中心判断。框选过窄可能漏检；画面预览会区分符合区域条件的黄色框与被过滤的灰色框。
- 本工具检测人体而非身份。背影、侧身、遮挡、暗光和小目标的效果应在实际工位校准。多人交叉可能导致轨迹换号，不能保证完全不重复或绝不漏检。
- “预览中”尚未启用提醒；“监测中”才运行人体检测。错误状态不表示无人。
- 未找到摄像头：检查 USB 连接和 Windows 设置中的相机权限、允许桌面应用访问相机。会议软件可能占用摄像头；停止本工具后再进行会议。
- 常规后端失败时，程序尝试按同一物理设备路径匹配兼容后端；无法可靠匹配时请手动选择。
- 摄像头硬件隐私盖关闭也可能仍有黑色画面，软件无法将所有黑暗场景与隐私盖准确区分。
- 完全隐藏到托盘后没有任务栏按钮，使用托盘图标提示。系统通知可能被 Windows 勿扰/通知设置拦截；应用自己的勿扰开关独立控制所有提醒渠道。
- 迷你窗口可拖动，点“折叠”缩成状态条；设置里选显示器和四角停靠位置。

**本地数据**

目录可自选：打开“设置 → 本地记录 → 更改目录”，选择本机空文件夹（例如 `D:\BehindWatch`），点击“保存”。软件会暂停监测、写完日志、复制设置/事件/截图，校验数据库并切换目录，随后恢复之前的监测或预览状态。原目录保留备份，不会覆盖目标目录中已有的数据。

“数据目录”栏显示当前路径，“打开当前数据目录”可直接打开。首次使用的默认目录仍为 `%LOCALAPPDATA%\BehindWatch`；更改后只有很小的目录位置记录和运行锁留在该启动目录中，新设置、日志和截图写入所选目录。旧数据备份可以在确认新目录正常后自行清理。

- `settings.json`：摄像头、区域、提醒等配置。
- `events.sqlite3`：事件日志，默认保留 7 天，最多 10000 条。
- `snapshots`：仅在显式开启截图后出现；保存触发时检测区域，默认上限 100 MB，按保留期限和容量清理。多人同时触发只保存一张。
- `startup-error.txt`：仅启动异常时生成，便于排查。

截图和事件保留规则在启动、设置变更和事件写入时执行。软件退出后可手动清空上述目录以重置。软件没有录像、云备份或远程上传功能；用户自行配置的第三方系统备份不在应用控制范围内。

**从 Python 源码运行**

本次构建使用 Python 3.11.15 x64；建议 Python 3.11 x64。联网安装依赖属于开发准备；发行包本身无需联网。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

模型和素材已随源码提供，不需要运行下载脚本。`tools/prepare.py` 仅用于构建时补齐缺失素材，不会被运行中的应用调用。

**测试与重新打包**

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/check.py
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean BehindWatch.spec
```

`requirements.lock` 记录本次构建的全部依赖。`tools/check.py` 生成模拟画面的界面截图，并把临时配置/测试截图写在临时目录，不读真实摄像头；`tools/camera_check.py` 和 `tools/runtime_check.py` 会短时间打开摄像头，仅输出统计，不保存真实画面。

运行目录在 `dist/BehindWatch`。自检命令 `BehindWatch.exe --smoke-test` 加载模型并自动退出，不打开摄像头。`--camera-smoke-test` 会短时间打开当前可用摄像头并自动退出，仅供开发验证。

**验证范围**

已在当前 Windows 11 x64 机器验证模型、内置摄像头、主要业务规则及界面。Windows 10、其他 USB 摄像头、多屏混合 DPI、休眠恢复及连续 8 小时运行尚未实机覆盖。详细数字和限制见随包测试报告。

第三方模型与依赖许可证见 `THIRD_PARTY_NOTICES.md` 和 `licenses`。应用未签名；是否运行由使用者按正常 Windows 提示决定，无需管理员权限。
